# Аудит приложения Shift — оглавление

Комплексный анализ Android-клиента игры Shift, выполненный 2026-07-22.
Фокус — **надёжность в бою** (игра ещё предстоит), безопасность — отдельным разделом,
красота кода намеренно вторична.

сильные стороны, единый список топ-проблем и приоритизированный план действий (P0/P1/P2).

## Система обозначений
- **Severity**: Critical → High → Medium → Low.
- **ID находок**: R# (reliability), T#/AU#/CH#/AR#/NO#/MA# (subsystems: Terminal/Aura/Chat/Artifact/Noise/Maps),
  S# (security), B# (build). На них ссылается executive summary.
- Ссылки на код — в формате `файл:строка`.

## Как это собиралось
- Прочитана вся кодовая база (~13.8k строк Kotlin), `AndroidManifest`, gradle-конфиги, ресурсы.
- Проект собран (`assembleDebug`, успешно) на JDK 17.
- Живой прогон на эмуляторе `Pixel_6_API_35` (Android 15) под игроком `Bas` и мастером `MG_Bas`:
  пройдены главный экран, профиль МГ, карта, терминал (в т.ч. мусорный ввод), поворот экрана.
  Крашей в основных флоу не зафиксировано; подтверждены вживую cleartext-HTTP, утечка тел
  сообщений в лог и тяжёлый поллинг.
- Часть разбора выполнена параллельными саб-агентами; спорные severity перепроверены вручную
  (например, T1 понижен с Critical до Medium-latent — см. пометку в 04-subsystems.md).

## Важные оговорки
- **Backend вне области** (`shift96.ru`, чат-сервер по IP) — оценивался только со стороны клиента.
- Баг **R1** (карта на Android ≤ 12) не воспроизводился на эмуляторе API 35 — нужен прогон на
  реальном устройстве с Android 11/12; логика в коде однозначна.
- Отчёт отражает состояние репозитория на момент аудита (ветка `master`, `versionCode 18 / 2.5`).
