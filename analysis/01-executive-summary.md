# 01. Итоговое резюме — приложение Shift

> Аудит от 2026-07-22. Клиент оффлайн-игры (квест/ролевая) на нативном Android
> (Kotlin, View + viewBinding). ~13.8k строк, 101 kt-файл, `versionCode 18 / 2.5`.
> Приоритет владельца: **надёжность в бою** (игра ещё предстоит, возможен повтор),
> красота кода вторична. Безопасность — отдельным разделом.
>
> Метод: статический разбор всей кодовой базы (частично силами саб-агентов),
> фактическая сборка, и живой прогон обеих ролей (`Bas`/`MG_Bas`) на эмуляторе API 35.

## Вердикт в двух абзацах

Приложение **живое и в целом работоспособное**: основные флоу обеих ролей на эмуляторе
отработали без крашей, парсер терминала устойчив к мусорному вводу, приложение переживает
поворот экрана, сеть деградирует «мягко» (пустые списки вместо падений). Видно, что об
устойчивости думали — везде try/catch, foreground-сервис с уведомлением, кэш против дублей
уведомлений, наблюдаемость (Crashlytics + Bugfender). Для игры «на один раз» база нормальная.

Но **надёжность держится на «обмазывании try/catch», а не на архитектуре**, и есть набор
конкретных дефектов, которые в полевых условиях (слабая сеть, старый телефон, много игроков
на карте, отправка фото, долгая сессия, Android 11/12) приведут к тихим отказам у отдельных
игроков: где-то не откроется карта, где-то подвиснет отправка фото, где-то не применится
игровой эффект, где-то мелькание маркеров. Ни одно — не «падает при старте», но каждое —
«у конкретного игрока в конкретный момент что-то отвалилось», а для выездной игры это дороже
красивого краша. Плюс три серьёзные security-проблемы (ключ подписи в репозитории, cleartext
HTTP с геолокацией живых людей, установка обновления без проверки целостности).

## Что сделано хорошо (не ломать)

- **Деградация вместо краха** — сеть падает → пустые списки/показ контента, а не вылет.
- **Foreground-сервис `location`** с уведомлением и проверкой runtime-разрешения — правильный
  выбор под геймплей «вошёл в зону → уведомление».
- **Наблюдаемость**: Crashlytics + Bugfender + уровневый `LogHelper` — для разового ивента
  это ценно (видно, что реально ломается у игроков).
- **Кэш «уже показанных» сообщений** в prefs снижает дубли уведомлений после рестарта.
- **`NoiseHelper`, `TerminalCommandManager`** — примеры уже вынесенной, изолированной логики;
  по их образцу стоит разгружать god-классы.
- **Терминал устойчив к вводу** (проверено вживую: мусор и сверхдлинные строки → аккуратная
  ошибка, без падения).

## План действий (приоритизированный, под надёжную игру)

### P0 — сделать до следующей игры (высокий эффект, низкая/средняя цена)

1. **Починить R1 (карта на Android ≤ 12).** Обернуть проверку/запрос `POST_NOTIFICATIONS`
   в `if (SDK_INT >= 33)`, а доступ к карте **отвязать** от разрешения на уведомления. _S._
   → без этого часть игроков со старыми телефонами просто не откроют карту.
2. **Логирование BODY/DEBUG только в debug** (S-04/R7) и **`debuggable false` + `minifyEnabled true`**
   для release (B1). _S–M_ (нужны keep-правила для Gson-моделей). → перестаёт течь приватность
   игроков и релиз становится «настоящим».
3. **Проверка sha256 в самообновлении** перед установкой + один путь завершения загрузки
   (S-02/R2). _S–M._ → защищает от битого и подменённого APK в разгар игры.
4. **Убрать секреты из репозитория** (S-01): новый keystore, пароли в `keystore.properties`/CI,
   вычистить историю. _M._ → закрывает главный security-вектор.
5. **CH1 — вынести чтение/загрузку вложения с UI-потока** (корутина на IO, стрим вместо
   `readBytes`). _S–M._ → отправка фото перестаёт вешать приложение.
6. **CH2 — починить `while(true)`-polling** (always `delay`, привязать к lifecycle). _S._
7. **NO1 — применять эффекты всех пройденных уровней шума** (цикл по порогам, не `when`). _S._
   → не теряется боевая механика при резких скачках шума.

### P1 — желательно к игре (заметный эффект)

8. **MA1/MA3 — не сносить всю карту каждые 10 с**: диффать точки (add/update/remove),
   перемещать существующие маркеры игроков, рассмотреть кластеризацию. _M–L._
9. **AU1 — кешировать bitmap проблем ауры** (декодировать один раз, как метки). _S._
10. **R3/CoroutineScope — заменить `GlobalScope`/голые скоупы на `lifecycleScope`** (массово).
    _M._ → убирает целый класс use-after-destroy крашей и утечек.
11. **HTTPS для бэкендов** (S-03). Требует работы на серверной стороне (домен+TLS для чат-IP),
    поэтому не P0, но важно. _L (вне клиента)._
12. **R4/R5 — прогнать фон на реальном устройстве** (экран заблокирован 30–60 мин, Doze),
    добавить просьбу отключить оптимизацию батареи; обработать рестарт сервиса. _M._
13. **CH3 — починить дублирование multipart** и привязку reply/тегов. _S._
14. **Ритуал (R6), USER.FORMAT (T6), MG map/chat override (#20)** — точечные фиксы. _S каждый._

### P2 — по возможности / гигиена (низкий приоритет, красота — не цель)

15. Убрать дубли Glide+Coil и RxJava (оставить корутины + одну image-либу); почистить
    packaging-костыли (B4/B5). _M._
16. Лимит истории терминала + Gson-адаптеры для `LocalTime`/`AuraMarkType` (T2/T2b/AU4). _S._
17. `allowBackup=false`, ограничить Maps-ключ по package+SHA-1, вынести Bugfender-токен. _S._
18. Разгрузка god-классов (Terminal 1273, EkatMaps 1237, LocationService 1030, MainActivity 837)
    — **только точечно** (парсер команд, CRUD точек), без большого рефакторинга ради красоты.

## Про архитектуру — коротко и прагматично

Паттерна нет: «толстые Activity», где экран сам себе UI + контроллер + сетевой слой; нет DI,
нет ViewModel, состояние живёт в полях и теряется при повороте. **Для игры «на один раз»
переписывать это на MVVM/Clean не окупается** — и не нужно. Прагматичный минимум, дающий
надёжность без переписывания: (1) `lifecycleScope` вместо голых скоупов, (2) новые правки
сети — на корутинах (не плодить третий способ), (3) вынести из god-классов только самые
хрупкие куски. Полную карту — в [02-architecture.md](02-architecture.md).
